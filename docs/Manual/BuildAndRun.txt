## Prerequisites
Laptop

   Engine: 28.5.1
   Compose: v2.40.3-desktop.1
   Kubernetes: v1.34.1 -> 1.29

## STEP 1 — Create an AWS IAM user for graphapp development
 - Jot down Access Key / Secret Key for CLI/eksctl
 - Attatch policies directly, AdministratorAccess, enable console access

## STEP 2 - Install CLI tools on your LapTop
 - Install AWS CLI
   > brew install awscli
   > aws configure # Enter the Access Key, Secret Key, default region (e.g., us-east-1), output format (json).
 - Install kubectl
   > brew install kubectl
 - Install eksctl
   > brew tap weaveworks/tap
   > brew install weaveworks/tap/eksctl
 - Install Helm (optional, for ALB controller)
   > brew install helm
 - Install Docker Desktop
   > sudo brew install --cask docker
 - Install MySQL client (to access MySQL on AWS)
   > brew install mysql-client@8.4 # couldn't log in when using mysql-client 9.5.0
 - Install Terraform
   > brew install tfenv
   > tfenv list-remote  # See all available versions
   > tfenv install 1.9.8  # Install specific version
   > tfenv use 1.9.8  # Switch to that version

## STEP 3 - Create EKS Cluster
 - Create cluster
```
# Check current AWS accoount & IAM user
aws sts get-caller-identity

# Create an EKS cluster
eksctl create cluster -f k8s/createCluster/cluster-config.yaml
```
 - See if Nodes are created
```
kubectl get nodes
```

## STEP 4 - Prepare Container Images
You can skip STEP 4 if ECR private repositories for frontend and backend already exist.
```
# Create Images (If not already created)
bash scripts/build_images.sh

# Create repositories
aws ecr create-repository --repository-name graphapp-eks-frontend
aws ecr create-repository --repository-name graphapp-eks-backend

# Login Docker to ECR
aws ecr get-login-password \
  | docker login --username AWS --password-stdin <AWS_ACCOUNT_ID>.dkr.ecr.<REGION>.amazonaws.com

# Tag images (Local Docker must be running)
docker tag frontend:latest <ACCOUNT_ID>.dkr.ecr.<REGION>.amazonaws.com/my-frontend:latest
docker tag backend:latest <ACCOUNT_ID>.dkr.ecr.<REGION>.amazonaws.com/my-backend:latest

# Push images
docker push <ACCOUNT_ID>.dkr.ecr.<REGION>.amazonaws.com/my-frontend:latest
docker push <ACCOUNT_ID>.dkr.ecr.<REGION>.amazonaws.com/my-backend:latest
```

## STEP 5 Deploy Your Kubernetes App
 - Update image references in your yaml files such that they point to your ECR images
 - Apply manifests
```
kubectl apply -f k8s/initials/namespace/
kubectl apply -f k8s/initials/
```

## STEP 6 Configure Ingress / ALB
Your Ingress controller will create an ALB endpoint.
```
# # Tag the subnets that k8s Worker Nodes belong to
# kubernetes.io/cluster/graphapp-eks-cluster = shared
# kubernetes.io/role/elb = 1 # if public subnets

# # Install the CRD of ALB (TargetGroupBinding: A Kubernetes Object is created that represents ALB instances)
# kubectl apply -k github.com/aws/eks-charts/stable/aws-load-balancer-controller/crds?ref=master

# Add Helm repo
helm repo add eks https://aws.github.io/eks-charts
helm repo update

# Enable OIDC provider (Without OIDC IRSA won't work: disabled by default)
'''
eksctl utils associate-iam-oidc-provider \
  --region ap-northeast-1 \
  --cluster graphapp-eks-cluster \
  --approve
'''

# Create IAM policy and Service Account (replace ACCOUNT_ID)
'''
  curl -O https://raw.githubusercontent.com/kubernetes-sigs/aws-load-balancer-controller/v2.6.1/docs/install/iam_policy.json
  # curl -O https://raw.githubusercontent.com/kubernetes-sigs/aws-load-balancer-controller/v3.0.0/docs/install/iam_policy.json
  aws iam create-policy \
    --policy-name AWSLoadBalancerControllerIAMPolicy \
    --policy-document file://iam_policy.json
  eksctl create iamserviceaccount \
    --cluster graphapp-eks-cluster \
    --namespace kube-system \
    --name aws-load-balancer-controller \
    --role-name AmazonEKSLoadBalancerControllerRole \
    --attach-policy-arn arn:aws:iam::<ACCOUNT_ID>:policy/AWSLoadBalancerControllerIAMPolicy \
    --approve

# Install controller (ALB will immediately be created)
helm install aws-load-balancer-controller eks/aws-load-balancer-controller \
  --version 1.6.1 \
  --set clusterName=graphapp-eks-cluster \
  --set serviceAccount.create=false \
  --set serviceAccount.name=aws-load-balancer-controller \
  --set region=ap-northeast-1 \
  -n kube-system

# Check the controller
kubectl get pods -n kube-system
kubectl logs -n kube-system \
  -l app.kubernetes.io/name=aws-load-balancer-controller

# Apply ingress.yaml
kubectl apply -f ./k8s/ingress/

# Check the ingress
kubectl get ingress -n graphapp　# ADDRESS of the created ALB should appear
kubectl describe ingress graphapp-ingress -n graphapp
```

## STEP 7 Database Setup
 - Create small RDS instance (t3.micro/t3.small graph-api-db-rds-mysql)
 - Allow inbound traffic from your working laptop's GIP* to port 3306 with Security Group
   * curl https://checkip.amazonaws.com # Check your GIP
     nc -zv <rds-endpoint> 3306 # Check connectivity
     mysql -h <rds-endpoint> -u <user> -p # log in to your RDS instance
 - Export your local database:
```
mysqldump -u graphapiuser -p GraphAPI > backup_graphapi.sql
```
 - Import into RDS:
```
mysql -h <rds-endpoint> -u <user> -p -e "CREATE DATABASE GraphAPI;"
mysql -h <rds-endpoint> -u <user> -p GraphAPI < dbbackup.sql
```

## STEP 8 Ensure all required Security Groups are created and attached
 -To ensure these SG are created, add the following annotation to ingress.yaml
  ALB: Client GIP -> http, 80
  EKS Node (Pod): ALB SG -> http, 3000, ALB SG -> http, 8080
  (Edit the client IP of sg-xxxxxxxxxxxxx (managed by controller) from 0.0.0.0/0 to your GIP)
```
alb.ingress.kubernetes.io/security-groups: "sg-xxxxxxxxxxxxx"
alb.ingress.kubernetes.io/manage-backend-security-group-rules: "true"
```
 -RDS: as in STEP 7

## STEP 9 Access Your App
```
# Verify that everything is running
kubectl get pods -n graphapp
kubectl get service -n graphapp
kubectl get ingress -n graphapp # check CLASS is nginx and ADDRESS is allocated

# (Optional) Check frontend and backend logs (-f show logs continuously)
kubectl logs -f -n graphapp deployment/frontend-deployment # frontend
kubectl logs -f -n graphapp deployment/backend-deployment # backend

# (Optional) Check Pods logs
kubectl logs -n graphapp <pod-name>

# Check the ALB DNS endpoint
kubectl get ingress -n graphapp
```
 - You’ll see ALB DNS endpoint
 - Open it in your browser → your frontend app is running in AWS
